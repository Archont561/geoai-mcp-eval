# Experiment Plugin

A minimal [qgis-sdk](https://pypi.org/project/qgis-sdk/) plugin generated by
`qgis-sdk new`. `experiment_plugin/plugin.py` holds the application and its actions,
without top-level Qt or QGIS imports, `classFactory`, or `metadata.txt`.
`host_observation.py` adapts host signals to session events; `session.py` owns
evidence persistence. `pyproject.toml` names the application
(`[tool.qgis-sdk] plugin`) and the few facts QGIS needs; `qgis-sdk build` and
`qgis-sdk dev` derive the QGIS entry from them. Replace the generated author
and email in `[project]` before publishing anywhere.

## Desktop mode

Use this when the plugin runs inside QGIS, which is the only host that provides
`iface`:

```sh
qgis-sdk dev
```

finds QGIS (`--qgis-prefix`, `[tool.qgis-sdk] qgis-prefix` in pyproject.toml,
`QGIS_PREFIX_PATH`, `qgis` on PATH, or the current environment), starts QGIS
Desktop with its own profile in `.qgis-sdk/profiles/dev`, writes a small host
package to `.qgis-sdk/dev/host/experiment_plugin/` (`metadata.txt` plus a
`classFactory` bound through `qgis_sdk.adapters.desktop.host()`) and puts that
directory on `QGIS_PLUGINPATH`, so QGIS loads `experiment_plugin/` from source, in
place. Saving a Python file (or the Reload button, Ctrl+Shift+R) unloads and
starts the current source again; a `pyproject.toml` change needs a new
`qgis-sdk dev`. A syntax error refuses the reload and keeps the running
revision; work that cannot stop within two seconds refuses it too and is named;
if unloading or starting fails the plugin stays disabled and the message says
so - restart `qgis-sdk dev`. `--no-watch` leaves reloads to the button. Quit
QGIS to stop.

To install into a real profile instead, `qgis-sdk build` writes
`dist/experiment_plugin-<version>.zip` with `metadata.txt`, the `classFactory` line and
the SDK runtime inside, and Plugins > Manage and Install Plugins > Install from
ZIP installs it in any supported QGIS without qgis-sdk.

## Standalone Qt mode

Use this when the code runs without QGIS, for example in a plain Qt application
or in the starter tests. `host()` gives the plugin exactly what the process can
offer:

```python
from qgis_sdk.adapters.desktop import host

plugin = host("experiment_plugin.plugin:app")(None)
plugin.initGui()
```

Without a `QgsApplication` the context has no `desktop`, so reading
`ctx.desktop` raises `QgisSdkUnsupportedCapabilityError` with
`code="unsupported_capability"` instead of inventing a host: standalone mode
provides no `iface`, no message bar and no plugin lifecycle. Informational
messages are dropped, because the notifications service has no bar to write
to. `qgis-sdk dev --mode standalone` runs the same entry in a bare
`QgsApplication`: no Desktop, no reload, close the window to stop. Run Qt
without a display by setting `QT_QPA_PLATFORM=offscreen`, which is what the
workspace smokes do.

## Human-baseline session recorder

The plugin records a human (H) baseline session for one pilot task: you click
**Start human-baseline session** (metadata is fetched automatically), perform
the task in QGIS, then click **End human-baseline session**. Nothing else is
recorded anywhere else and `human_baseline.status` in the task YAML stays
`pending` until you review the evidence.

### Actions

| action | what it does |
| --- | --- |
| `start_session` | `task_id` (default `prep-axis-order-001`), `base_dir` (default `$EXPERIMENT_TASK_DIR` or `experiment/tasks`), `participant_code` (optional). Validates the task id against the suite, hashes the task YAML and fixture, creates the gitignored per-session output dir `experiment/tasks/baselines/<task_id>/session-<started_at_utc>/`, starts the UTC timer, and connects best-effort host hooks (QGIS project layer add/remove, CRS change, project read; canvas extent/scale). The record's `network_disabled` stays `null`: the host cannot verify network isolation — disable the network yourself and record that in a `log_note`. |
| `log_note` | `message` — records a note/deviation/interruption in the event log. |
| `show_timer` | opens the non-modal **session panel** ("Human-baseline session", menu Plugins > Experiment Plugin): a tabbed window — see below. Opens idle when no session is active (press Start inside it); in a headless host without a GUI capability it answers with a message instead of raising. |
| `abandon_session` | abandons the active session WITHOUT writing `human-reference-record.json`. The event log stays on disk and gains a `session_abandoned` marker event plus a `session-abandoned.json` next to it. Evidence is kept but never promoted to reference data; task YAML `human_baseline.status` is untouched. |
| `end_session` | stops the timer, hashes top-level output files other than the event log and record, writes `human-reference-record.json` and appends a `session_end` event to `events.jsonl` — both in this session's own `session-<started_at_utc>/` directory (restarts never share an evidence file). See the host-hook limitation below. |
| `hello` | original demo action, harmless. |

### Session panel (Timer / Logs)

`show_timer` opens one tabbed, non-modal window. Closing it never stops the
recording.

**Timer tab.** Task id field (prefilled, editable while idle), optional
participant code, a live HH:MM:SS counter and three buttons that drive the
actual session, not just the display:

- **Start** — starts a session through the same path as `start_session`
  (default task suite = `$EXPERIMENT_TASK_DIR` or `experiment/tasks`).
- **Stop** — ends the session through the same path as `end_session`; the
  record is written and the counter freezes on the last reading.
- **Restart** — abandons the current session (evidence stays on disk, marked
  `session-abandoned.json`, NO record written) and immediately starts a fresh
  session with the same task/participant — only after a confirmation prompt.

**Logs tab.** A live rendering of the active session's `events.jsonl` (auto-
refreshes every 2 s; Refresh forces it), one line per event with sorted
`key=value` fields. **Export…** writes the same human-readable rendering to a
file you pick in a save dialog (`<session-dir>-events.txt` by default).
After the session ends or is abandoned, the tab and Export keep showing the
last finished session.

Widgets carry `objectName`s (`sessionTaskEdit`, `sessionStartButton`, …) for
agents and tests (decision-51). The Qt layer is exercised by fake-Qt unit
tests in the pure suite and was additionally smoked with real Qt offscreen
(`QT_QPA_PLATFORM=offscreen`).

### What is fetched automatically vs. what stays blank

Fetched: task id, task YAML SHA-256, fixture SHA-256, UTC start/end and elapsed
minutes, event count (steps excl. the start/end markers), tools used, QGIS /
GDAL / GEOS / PROJ software versions from the host (or `null` outside QGIS),
Python/platform facts (no hostname or user name), SHA-256 and size of each
top-level output file other than the event log and record.

Never invented (stays `null`): participant code unless you pass one, consent,
screen recording, `network_disabled` (the host cannot enforce or verify it), oracle report path and `oracle_passed` — those are filled by
you and by `pixi run experiment pilot determinism <task_id> --artifacts-dir
experiment/tasks/baselines/<task_id>/session-<started_at_utc>` afterwards.

### Host notes

Inside QGIS Desktop actions appear per their bindings; only `show_timer` is
bound (Plugins > Experiment Plugin) today — the rest are unbound in the GUI
for now; from the panel, Start / Stop / Restart reach them through the
runtime like any bridge call. The host hooks connect lazily
and degrade silently when the host provides no project or canvas (server
hosts, standalone tests). The behavior event log (`events.jsonl`, one per
session directory) is the raw evidence; the record is the summary. Cap: 2000
events per session (extent events can flood).

## Known limitations

- **Host hooks outlive sessions.** Project and canvas callbacks remain connected
  after a session ends or is abandoned. Later host activity can append to earlier
  logs, including after a restart. Resolve this before treating those logs as
  closed evidence.
- **Event summaries differ from study metrics.** The record counts observed
  events and notes as steps, and lists observation sources as tools. Determine
  human steps and tools from processing history and manual review separately.
- **One active session at a time.** The plugin keeps a module-global singleton
  (`_ACTIVE`); it cannot represent two concurrent sessions (e.g. two projects).
  Starting a second session while one is active is refused. A real fix needs a
  registry keyed by project, not the singleton.
- **Restart is destructive to the timer, not the files.** `Restart` in the panel
  abandons the current take: no record is written and the YAML status stays
  `pending`, but `events.jsonl` and `session-abandoned.json` remain in the
  session directory for audit. Abandoned takes are never reference evidence.
- **Action results are human-readable strings**, not typed success/error values.
  `start_session` reports failure as text mixed with the success summary — fine
  for a desktop action label, unusable as a machine-readable status; do not parse it.
- **Version sync is test-pinned, not shared.** `qgis-sdk build` rejects PEP 621
  dynamic versions (META002), so `pyproject.toml` carries a literal version that
  must equal `experiment_plugin.__version__`; `tests/test_plugin.py` fails the
  suite if they drift. Bump both together (and `qgis-sdk` check grounds expectations).

## Tests

```sh
qgis-sdk test                    # pure: no QGIS, native imports refused
qgis-sdk test --target qgis      # tests marked `qgis`, headless QgsApplication (`qgis_app`)
qgis-sdk test --target desktop   # tests marked `desktop`, inside QGIS Desktop (`qgis_iface`)
pytest -q                        # the same suite, your way
```

Arguments the command does not know go to pytest (`qgis-sdk test -x -k ping`).
A native target whose QGIS cannot be found fails; one whose tests all skipped
fails too.
